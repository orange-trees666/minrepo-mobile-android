# みんレポ抽出 Android版

PixelなどのAndroid端末だけで、みんレポの公開レポートを取得・集計する
.NET MAUIアプリです。APKを一度インストールした後は、PCやサーバーを起動せずに
スマートフォンだけで実行できます。

## できること

- 店舗の`/tag/`ページから指定期間の日別レポートを取得
- 日別レポートURLを指定して1日分だけ取得
- 日毎・週毎（月曜始まり）・月毎を選んで集計
- 機種・出率帯・台番末尾・1機種あたり設置台数を選んで集計
- 店舗全体の総差枚を日・週・月ごとに出力
- 台番ごとのG数、総回転数、出率、BB、RB、合成、BB率、RB率を出力
- 分割された全台表・機種詳細表を「レポートトップに戻る」まで全件結合
- 全台ページで負数が省略表示された台を保留し、機種詳細ページの差枚・出率から復元
- 対象列の見出しを持つ表だけを列名ベースで解析し、広告表・グラフ表を除外
- レポートトップの勝率分母・総差枚と、全台解析件数・差枚合計を照合
- 機種ごとの中央値、ばらつき、プラス日率、勝率、稼働、突出台依存率等を評価
- 取得失敗時に「作成しない」または「取得済み分で作成」を画面から選択
- 部分出力では、ページ・台番・検証項目ごとの失敗をCSVへ記録して処理を継続
- 取得中の進捗表示と中止
- 10種類のCSVと取得情報JSONをZIP化
- Androidの共有画面からFilesやGoogle Driveへ保存
- ネット接続を使わない3台・2機種の動作テスト

## 画面操作

1. `店舗一覧`または`1日分`を選択します。
2. みんレポのURLを貼り付けます。
3. 店舗一覧の場合は開始日・終了日・最大レポート数を指定します。
4. 日・週・月と、機種・出率帯・末尾・設置台数から必要な集計条件を選びます。
5. BB・RB等も必要なら`BB・RB・合成確率まで取得`を選びます。
6. 取得失敗時の出力方法を選びます。
7. `取得を開始`を押します。
8. 完了後、`結果ZIPを保存・共有`を押します。
9. Androidの共有画面でFiles、Google Drive等を選びます。

日付欄または`開始日を選択`・`終了日を選択`ボタンからAndroidの日付画面を開けます。
確定した日付はボタン表示と内部の取得条件の両方へ反映されます。

取得中は画面を開いたままにしてください。アプリは実行中だけ画面消灯を抑止します。
BB・RB等の詳細取得は日別・機種別ページにもアクセスするため、日数と機種数に
比例して時間と通信量が増えます。長期間を一度に取得せず、まず1週間程度で確認してください。

## 出力ファイル

| ファイル | 内容 |
|---|---|
| `00_取得失敗一覧.csv` | 取得できなかった処理箇所、URL、内容。失敗なしの場合はヘッダーのみ |
| `01_台別詳細.csv` | 1日・1台単位。G数、総回転数、出率、BB、RB、合成、BB率、RB率 |
| `02_日別_機種別.csv` | 店舗・日付・機種別 |
| `03_日別_末尾別.csv` | 店舗・日付・末尾別 |
| `04_日別_設置台数別.csv` | 日別の設置台数別 |
| `05_期間_機種別.csv` | 期間全体の機種別 |
| `06_期間_末尾別.csv` | 期間全体の末尾別 |
| `07_期間_設置台数別.csv` | 期間全体の設置台数別 |
| `08_日週月_可変集計.csv` | 選択した期間・キーの集計。`集計キー=店舗全体`で店全体の総差枚 |
| `09_機種評価.csv` | 扱いの良い機種を比較するための安定性・稼働・勝率等 |
| `取得情報.json` | 取得件数、失敗URL、注意事項 |

CSVはExcelで文字化けしにくいUTF-8 BOM付きです。

### 項目上の注意

- みんレポの公開表では`G数`が回転数として掲載され、別の「総回転数」項目はありません。
  このため`総回転数`列には同じG数を収録しています。
- `BB`、`RB`、`合成`、`BB率`、`RB率`は詳細取得を選んだ場合だけ入ります。
- 全台ページで差枚・出率が`-`だけになった台は、機種詳細ページを機種単位で取得して
  マイナス差枚を含む完全な行へ復元します。この復元は詳細取得の選択にかかわらず行います。
- BB/RB列が存在しない機種でも、台番・差枚・G数・出率は取得を継続します。
- `取得済み分で作成`では、全件失敗して台データが0件でも、各CSVのヘッダー、
  `00_取得失敗一覧.csv`、`取得情報.json`を含むZIPを作成します。
- `1件でも取得できなければ作成しない`では、取得・解析・件数照合・総差枚照合・
  詳細取得のいずれか1件でも失敗した場合、ZIPを作成しません。
- 出率帯は`90%未満`、`90%以上100%未満`、`100%以上105%未満`、
  `105%以上110%未満`、`110%以上`、`不明`です。
- 週は月曜日から日曜日までです。取得期間の端にある週・月は、取得できた日だけで集計します。

## 扱いの良い機種を見るときの指標

`09_機種評価.csv`には、単純な総差枚だけで判断しないため、次を収録しています。

- `対象日数`、`台日数`、`稼働台日数`、`平均G数`: 標本量と実際の稼働
- `中央値差枚`、`差枚標準偏差`: 1台の大勝ちに引っ張られていないか
- `機種プラス日率`、`勝率`、`105%以上率`、`110%以上率`: 良い結果の再現性
- `0G率`、`詳細取得率`: 欠測や低稼働による判断の弱さ
- `最大勝ち台依存率`: プラス差枚のうち最大勝ち台1台が占める割合
- `データ充足度`: 5日以上かつ稼働20台日以上をひとつの目安として表示

曜日・特定日・月内の位置でも結果が変わるため、`08_日週月_可変集計.csv`と
台別詳細を組み合わせて確認してください。差枚や出率だけから設定投入を断定する
ことはできず、低稼働、偶然の偏り、機種仕様も考慮する必要があります。

## Androidへ最初にインストールする

アプリの実行はAndroidだけで完結しますが、APKの初回ビルドには
Windows PCとVisual Studio、またはGitHub Actionsなどのビルド環境が必要です。

### Visual Studioから直接インストールする方法

1. Visual Studio Installerで`.NET Multi-platform App UI development`を導入します。
2. `MinRepoMobile/MinRepoMobile.csproj`をVisual Studioで開きます。
3. Pixel 7aで`設定 > デバイス情報 > ビルド番号`を7回タップし、開発者向けオプションを有効にします。
4. `設定 > システム > 開発者向けオプション > USBデバッグ`を有効にします。
5. Pixel 7aをUSB接続し、端末側でPCを許可します。
6. Visual Studio上部の実行対象からPixel 7aを選択し、開始ボタンを押します。

これでデバッグ署名されたアプリがPixel 7aへインストールされます。
以後、ホーム画面の`みんレポ抽出`からスマホ単体で起動できます。

### 署名済みAPKを作る方法

Visual Studioでプロジェクトを右クリックし、`発行`からAndroidの
アドホック配布を選択します。APKを端末へ渡し、Pixel 7a側でインストールします。

CLIを使用する場合の例は次のとおりです。パスワードはコマンドへ直接書かず、
環境変数を使ってください。

```powershell
$env:MINREPO_KEY_PASS = "自分で決めたパスワード"

dotnet publish .\MinRepoMobile\MinRepoMobile.csproj `
  -f net10.0-android `
  -c Release `
  -p:AndroidPackageFormats=apk `
  -p:AndroidKeyStore=true `
  -p:AndroidSigningKeyStore=minrepo.keystore `
  -p:AndroidSigningKeyAlias=minrepo `
  -p:AndroidSigningKeyPass=env:MINREPO_KEY_PASS `
  -p:AndroidSigningStorePass=env:MINREPO_KEY_PASS
```

署名鍵とパスワードを紛失すると、同じアプリIDの更新版を署名できなくなるため、
安全な場所へ保管してください。

## 通信と端末権限

- 通信先はHTTPSの`min-repo.com`だけに制限しています。
- `robots.txt`を確認できない場合や取得が禁止されている場合は停止します。
- リクエスト間隔は1.5秒で、最大100レポートに制限しています。
- 日別レポートは公開後に台数が更新される場合があるため、永続キャッシュせず毎回確認します。
- 日別レポートトップも確認し、`勝率 160/371`の分母および掲載総差枚を、
  全台取得件数・明細の差枚合計と照合します。
- 一時的なHTTP 429、500、502、503、504だけ最大3回再試行します。
- ストレージ、位置情報、連絡先、カメラ等の権限は要求しません。
- 結果ZIPはアプリ専用キャッシュの`sharing-root`だけをAndroidへ共有します。

## 注意事項

- 個人分析用の取得を想定しています。大量・高頻度の取得は避けてください。
- サイト構造や利用条件が変更された場合は、解析できなくなる可能性があります。
- みんレポは掲載値が独自調査値で、実値と異なる可能性があると説明しています。
- 引用・外部公開時は、CSVの`出典URL`を併記してください。
- アプリを閉じたり、画面を消したり、Androidがプロセスを終了した場合は処理が中断されます。

## 主な構成

```text
MinRepoMobile/
├─ MainPage.xaml / MainPage.xaml.cs        画面と操作
├─ Models/ExtractionModels.cs              入出力モデル
├─ Services/MinRepoExtractionService.cs    処理全体の制御
├─ Services/RespectfulMinRepoClient.cs     通信・robots・待機・再試行
├─ Services/MinRepoHtmlParser.cs           HTML解析
├─ Services/CsvZipExporter.cs              集計・CSV・ZIP
└─ Platforms/Android/                      Android権限と共有設定
```

## 動作テスト

アプリ画面の`通信なしで動作テスト`を押します。

自己テストでは、分割表、列順の異なる表、広告用の数値表、グラフ表、
全台ページで差枚・出率が`-`だけの負数行、終了リンク後のランキングを混在させています。
次の結果になれば、対象表の判定、負数行の詳細ページ復元、
全台数照合、HTML解析、BB/RB詳細の結合、日・週・月および店舗全体の集計、
10種類のCSV作成、取得0件時の失敗一覧、ZIPの再読込まで動作しています。

- 店舗: テスト店舗
- 日付: 2026-07-27
- 機種: 機種A 2台、機種B 1台
- 合計差枚: +900
- BB合計: 15、RB合計: 18
- 完了表示: `1日分 / 3台日`
